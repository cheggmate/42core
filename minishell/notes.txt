Ah, great question 👀

Short answer: **not really — but they’re related**.

---

### 🔹 Pipex bonus

* Goal: **implement multiple pipes** (`./pipex infile cmd1 cmd2 ... cmdN outfile`).
* You don’t parse complicated input — the commands are already separated in `argv`.
* The logic is mainly about:

  * Handling **n pipes** in a loop.
  * Redirecting input/output correctly.
  * Waiting for multiple children.

So pipex bonus is mostly **plumbing** (pipes + forks + dup2 in loops).

---

### 🔹 Minishell lexer

* Goal: **parse a raw shell input string** like:

  ```
  cat infile | grep "foo bar" | wc -l > outfile
  ```
* You don’t get commands split into `argv` for free.
* The lexer’s job is to:

  * Split by tokens (`|`, `<`, `>`, `>>`, words, quoted strings).
  * Preserve grouping (`"foo bar"` stays one argument).
  * Hand those tokens to the parser, which then builds a structure you later execute.

So minishell’s lexer is **about understanding and splitting the input text into meaningful tokens**.

---

### 🔹 The connection

* The **execution engine of minishell** (after parsing) is very much like **pipex bonus**:

  * Loop through commands connected by pipes.
  * Set up `dup2` redirections.
  * Use `execve` to run each command.
* But before you can even get there, minishell needs the **lexer + parser** to *figure out* what the commands and operators are.

---

✅ So you can think of it this way:

* **Pipex bonus** teaches you the execution engine for multiple pipes.
* **Minishell lexer** teaches you how to break down a raw command line into the `argv` and redirection structure that the execution engine can consume.

void print_ast(t_ast *node, int depth)
{
    if (!node) return;
    for (int i = 0; i < depth; i++) printf("  ");

    switch (node->type)
    {
        case NODE_COMMAND:
            printf("COMMAND:");
            for (int i = 0; node->argv && node->argv[i]; i++)
                printf(" %s", node->argv[i]);
            printf("\n");
            break;
        case NODE_PIPE:
            printf("PIPE\n");
            break;
        case NODE_REDIR_OUT:
            printf("REDIR_OUT -> %s\n", node->filename);
            break;
        default:
            printf("NODE %d\n", node->type);
    }
    print_ast(node->left, depth+1);
    print_ast(node->right, depth+1);
}



char *getenv_value(char **env, const char *key)
{
    int i;
    size_t len;

    if (!env || !key)
        return NULL;

    len = strlen(key);
    i = 0;
    while (env[i])
    {
        if (strncmp(env[i], key, len) == 0 && env[i][len] == '=')
            return env[i] + len + 1; // skip "KEY="
        i++;
    }
    return NULL;
}

heredoc redirect explanation

pipe(pipe_fd) creates a pipe:

pipe_fd[0] → read end

pipe_fd[1] → write end

We read lines from the user using getline().

Each line is written into the pipe until the limiter is matched.

After finishing, the write end is closed, and the read end is redirected to stdin with dup2.

Any command executed after this reads from the heredoc input as if it were stdin.
